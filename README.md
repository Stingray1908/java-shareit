# README

## Приложение для обмена вещами

Веб‑приложение, позволяющее пользователям делиться вещами: размещать их в общий доступ, запрашивать во временное пользование, бронировать и оставлять отзывы.

## Ключевые концепции

* **Пользователь** — участник платформы (владелец или арендатор вещей).
* **Вещь** — предмет, доступный для бронирования (например, инструмент, техника, инвентарь).
* **Запрос** — предварительное намерение получить вещь. Создаётся пользователем до бронирования, чтобы выразить интерес.
* **Бронирование** — подтверждённое соглашение об использовании вещи на конкретные даты. Требует подтверждения владельцем.
* **Отзыв** — оценка вещи после завершения бронирования. Доступен только тем, кто реально пользовался вещью.

## Роли и права доступа

**Владелец вещи может:**
* добавлять, редактировать и удалять свои вещи;
* видеть запросы на свои вещи;
* подтверждать или отклонять бронирования;
* просматривать отзывы о своих вещах.

**Арендатор может:**
* создавать запросы и бронирования на чужие вещи;
* отменять свои бронирования;
* оставлять отзывы после завершения бронирования;
* искать и просматривать вещи.

**Все пользователи могут:**
* искать вещи по названию или описанию;
* просматривать публичные данные о вещах и отзывах;
* регистрироваться и управлять своим профилем.

## Основные возможности

### Управление пользователями
* регистрация новых пользователей (требуется имя и email, email должен быть уникальным);
* просмотр данных конкретного пользователя или списка всех пользователей;
* редактирование профиля (имя и email);
* удаление учётной записи.

### Работа с запросами на вещи
* создание запроса на получение вещи;
* обновление статуса запроса (например, «в обработке», «отклонён» и т. д.);
* просмотр своих запросов или всех запросов в системе;
* удаление собственного запроса.

### Управление вещами
* добавление новых вещей в каталог (с описанием и статусом доступности);
* редактирование информации о своих вещах (название, описание, доступность);
* просмотр списка своих вещей;
* поиск вещей по названию или описанию (поиск без учёта регистра);
* просмотр подробной информации о любой вещи;
* удаление своих вещей из каталога.

### Бронирование вещей
* создание бронирования для интересующей вещи (с указанием дат использования);
* подтверждение или отклонение бронирования владельцем вещи;
* отмена бронирования пользователем, который его создал;
* просмотр информации о конкретном бронировании или списке бронирований;
* отслеживание статусов бронирований.

### Отзывы (комментарии) о вещах
* оставление отзыва о вещи — доступно только тем, кто успешно завершил её бронирование;
* каждый пользователь может оставить только один отзыв на конкретную вещь;
* редактирование собственного отзыва;
* удаление собственного отзыва;
* просмотр всех отзывов о конкретной вещи (доступен всем пользователям).


## Статусы сущностей

### Запрос
* **Возможные статусы:**
    * `PENDING` — ожидает ответа;
    * `RESPONDED` — обработан;
    * `CANCELLED` — отменён;
    * `COMPLETED` — завершён.
* **Кто меняет:** владелец вещи или автор запроса.
* **Ограничения:**
    * нельзя установить `PENDING` или `RESPONDED` вручную;
    * нельзя менять статус для `CANCELLED` и `COMPLETED`.

### Бронирование
* **Возможные статусы:**
    * `WAITING` — ожидает подтверждения;
    * `APPROVED` — подтверждено;
    * `REJECTED` — отклонено;
    * `COMPLETED` — завершено;
    * `CANCELED` — отменено.
* **Кто меняет:**
    * владелец — подтверждает (`APPROVED`) или отклоняет (`REJECTED`);
    * арендатор — отменяет (`CANCELED`).
* **Ограничения:** нельзя изменить статус для `REJECTED`, `CANCELED`, `COMPLETED`.

## Ограничения и правила

* Email пользователя уникален (попытка создать пользователя с существующим email приводит к ошибке).
* Описание вещи не может превышать 100 символов.
* Текст отзыва не может быть пустым и не должен превышать 1000 символов.
* Один пользователь может оставить только один отзыв на конкретную вещь.
* Пользователь не может бронировать свои собственные вещи.
* Запрещено создавать пересекающиеся бронирования для одной вещи.
* Время начала брони должно быть в будущем и меньше времени окончания.
* Пользователь не может иметь несколько активных бронирований одной вещи.

## Аутентификация и авторизация

Для операций, требующих авторизации, используется заголовок `X‑User‑Id` с ID пользователя. Это позволяет:
* подтвердить личность пользователя;
* проверить права доступа (например, владелец ли вещи);
* связать действия с конкретным пользователем (создание, редактирование, удаление).

## Формат ответов API

API возвращает данные в формате JSON. Примеры:

* При создании пользователя: `UserSendDTO` с присвоенным ID.
* При создании вещи: `ItemSendDTO` с ID вещи и данными владельца.
* При бронировании: `BookingSendDto` с ID бронирования и текущим статусом (`WAITING`).
* При оставлении отзыва: `CommentSendDto` с ID отзыва и текстом.

## Краткий итог

Приложение создаёт платформу для совместного использования вещей:
* пользователи предлагают свои предметы другим;
* запрашивают нужные им вещи;
* бронируют их на определённые даты;
* делятся впечатлениями через отзывы.
