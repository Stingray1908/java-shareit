# ShareIt — сервис аренды вещей


Веб‑сервис для аренды и обмена вещами между пользователями. Позволяет создавать объявления о сдаче вещей в аренду, бронировать их, оставлять комментарии и управлять запросами.


## Технологии


* **Spring Boot** — основа приложения, автоконфигурация, внедрение зависимостей.
* **JPA / Hibernate** — работа с реляционной базой данных.
* **Lombok** — сокращение шаблонного кода (геттеры, сеттеры, конструкторы).
* **SLF4J** — логирование.
* **Jakarta Validation** — валидация данных на уровне контроллера.
* **PostgreSQL** (предполагаемая БД) — хранение данных пользователей, вещей, бронирований, запросов и комментариев.

## Функциональные возможности

### Пользователи (`User`)


* Регистрация нового пользователя.
* Просмотр информации о конкретном пользователе.
* Получение списка всех пользователей.
* Редактирование данных пользователя (частичное обновление).
* Удаление учётной записи пользователя.

### Вещи (`Item`)


* Создание новой вещи для аренды.
* Редактирование информации о вещи (частичное обновление).
* Просмотр подробной информации о вещи.
* Поиск вещей по ключевым словам в названии или описании.
* Удаление вещи из системы.
* Просмотр списка всех вещей пользователя.
* Добавление комментариев к вещи (только для пользователей, которые ранее арендовали эту вещь).

### Бронирования (`Booking`)

* Создание запроса на бронирование вещи.
* Подтверждение или отклонение запроса на бронирование (владельцем вещи).
* Просмотр информации о конкретном бронировании.
* Фильтрация списка бронирований пользователя по статусу (все, текущие, прошлые, будущие, ожидающие подтверждения, отклонённые).
* Просмотр бронирований для всех вещей владельца с фильтрацией по статусу.

### Запросы (`Request`)


* Создание запроса на предоставление вещи (когда пользователь ищет конкретную вещь).
* Частичное обновление статуса запроса.
* Просмотр конкретного запроса.
* Просмотр всех запросов текущего пользователя.
* Удаление запроса.

## API Endpoints

### Управление пользователями (`/users`)


| Метод | Эндпоинт | Описание |
|------|----------|----------|
| `POST` | `/users` | Создать пользователя |
| `PATCH` | `/users/{userId}` | Обновить данные пользователя |
| `GET` | `/users/{userId}` | Получить пользователя по ID |
| `GET` | `/users` | Получить всех пользователей |
| `DELETE` | `/users/{userId}` | Удалить пользователя |

### Управление вещами (`/items`)

| Метод | Эндпоинт | Описание |
|------|----------|----------|
| `POST` | `/items` | Создать вещь |
| `PATCH` | `/items/{itemId}` | Обновить вещь |
| `GET` | `/items/{id}` | Получить вещь по ID |
| `GET` | `/items` | Получить вещи пользователя |
| `GET` | `/items/search` | Поиск вещей по подстроке в названии или описании |
| `DELETE` | `/items/{itemId}` | Удалить вещь |
| `POST` | `/items/{itemId}/comment` | Добавить комментарий к вещи |

### Управление бронированиями (`/bookings`)

| Метод | Эндпоинт | Описание |
|------|----------|----------|
| `POST` | `/bookings` | Создать бронирование |
| `PATCH` | `/bookings/{bookingId}` | Подтвердить/отклонить бронирование |
| `GET` | `/bookings/{bookingId}` | Получить бронирование по ID |
| `GET` | `/bookings` | Получить бронирования пользователя с фильтрацией по состоянию |
| `GET` | `/bookings/owner` | Получить бронирования вещей владельца с фильтрацией по состоянию |

### Управление запросами (`/requests`)

| Метод | Эндпоинт | Описание |
|------|----------|----------|
| `POST` | `/requests` | Создать запрос |
| `PATCH` | `/requests/{requestId}` | Обновить статус запроса |
| `GET` | `/requests/{requestId}` | Получить запрос по ID |
| `GET` | `/requests` | Получить все запросы пользователя |
| `DELETE` | `/requests/{requestId}` | Удалить запрос |

## Заголовки запросов


Все запросы, требующие указания ID пользователя, используют кастомный заголовок:

* `X-Sharer-User-Id` — ID пользователя для операций с вещами, бронированиями, комментариями.
* `X-Requestor-User-Id` — ID пользователя для операций с запросами.

## Статусы и состояния

### Статусы бронирования (`BookingStatus`)

| Статус | Описание | Когда присваивается |
|-------|---------|------------------|
| `WAITING` | Ожидание подтверждения | При создании бронирования (начальный статус) |
| `APPROVED` | Подтверждено | После того как владелец вещи подтвердил бронирование |
| `REJECTED` | Отклонено | После того как владелец вещи отклонил бронирование |
| `CANCELLED` | Отменено | Когда пользователь отменил бронирование до его начала |
| `COMPLETED` | Завершено | После окончания периода бронирования (дата `end` прошла) |

#### Особенности жизненного цикла

1. **Начальное состояние**: любое бронирование создаётся со статусом `WAITING`.
2. **Подтверждение/отклонение**: только владелец вещи может изменить статус с `WAITING` на `APPROVED`/`REJECTED`.
3. **Отмена пользователем**: пользователь (`booker`) может отменить бронирование (перевести в `CANCELLED`), если оно ещё не началось и не отклонено.
4. **Автоматическое завершение**: система автоматически переводит бронирование в статус `COMPLETED`, когда текущая дата превышает дату `end`.
5. **Необратимость**: после установки статусов `REJECTED`, `CANCELLED` или `COMPLETED` статус не может быть изменён.

### Состояния для фильтрации (`BookingState`)


* `ALL` — все бронирования.
* `CURRENT` — текущие бронирования (период включает текущий момент).
* `PAST` — прошлые бронирования (завершились до текущего момента).
* `FUTURE` — будущие бронирования (начнутся после текущего момента).
* `WAITING` — ожидающие подтверждения.
* `REJECTED` — отклонённые бронирования.


### Статусы запроса (`RequestStatus`)


* `PENDING` — ожидает обработки.
* `RESPONDED` — на него откликнулись (есть предложения).
* `CANCELLED` — отменён пользователем.
* `COMPLETED` — успешно завершён.

## Бизнес‑правила


1. **Владелец не может бронировать свои вещи.**
2. **Вещь должна быть доступна** (`available = true`) для создания бронирования.
3. **Даты бронирования должны быть корректны:** `start < end`, `start` в будущем.
4. **Не допускается пересечение бронирований** по времени для одной вещи.
5. **Подтверждение возможно только для статуса `WAITING`.**
6. **Доступ к данным бронирования имеют только `booker` (тот, кто бронировал) и `owner` (владелец вещи).**
7. **Комментарий к вещи может оставить только пользователь, который ранее арендовал эту вещь.**
8. **Email пользователя должен быть уникальным.**
9. **При обновлении вещи хотя бы одно поле должно быть заполнено.**
10. **При создании запроса автоматически устанавливается статус `PENDING` и фиксируется время создания.**


### Запуск PostgreSQL в Docker

```bash
docker run --name shareit-postgres \
  -e POSTGRES_DB=shareit_db \
  -e POSTGRES_USER=sa \
  -e POSTGRES_PASSWORD=111 \
